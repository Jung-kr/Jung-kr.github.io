**낚시없는 우리집**은 고령층을 중심으로 급증하는 **보이스피싱, 메신저 피싱 등 디지털 금융사기 피해를 예방**하기 위해 개발된 교육 서비스입니다. 핵심 아이디어는 **실제 사기 상황을 체험하며 자연스럽게 대처법을 학습하는 것**입니다. 친숙한 책방 컨셉으로 설계되어, 어르신들이 서점을 구경하듯 편안하게 다양한 사기 시나리오를 경험할 수 있습니다.  
특히 AI가 최신 디지털 금융사기 뉴스를 자동 반영하여 시나리오를 업데이트하고, 가족의 목소리로 교육을 제공하여 고령층이 자연스럽게 몰입할 수 있습니다.

## 🏠 시나리오 설계 방향

---

아래 사진은 `easyarumm`에서 제공하는 사기 시뮬레이터의 시나리오입니다. 다만 `easyarumm`은 보이스피싱과 메신저 피싱 같은 **고정된 시나리오만 제공**하기 때문에, 급격히 변화하는 디지털 금융사기의 최신 수법을 충분히 반영하기 어렵습니다.

<img src="/assets/img/devlog/09/dev09_1.png" alt="velog 404" style="display: block; margin: 0 auto; max-width: 900px; max-height: 600px;">

저희 서비스는 이를 보완하기 위해 **매일 00시에 최신 디지털 금융사기 관련 뉴스를 크롤링하고, 해당 뉴스 내용을 기반으로 새로운 시나리오를 자동 생성**합니다. 이렇게 하면 시뮬레이터에 **날마다 새로운 사례가 추가**되어, 어르신들이 최신 사기 수법에 반복적으로 노출되면서 학습 효과를 높일 수 있습니다. 그렇다면 최신 뉴스를 어떻게 시나리오로 바꿀 수 있을까요?

<img src="/assets/img/devlog/09/dev09_2.png" alt="velog 404" style="display: block; margin: 0 auto; max-width: 900px; max-height: 600px;">
 
- **데이터 수집 (뉴스 크롤링)**
  - 디지털 금융사기 관련 키워드로 뉴스 자동 크롤링
  - 예: "보이스피싱", "메신저 피싱", "금융사기" 등
- **데이터 전처리 (필터링)**
  - 수집한 뉴스에서 광고·불필요한 문구·개인정보 등을 제거
  - 핵심은 **사기 수법과 피해 상황만 추출**
- **시나리오 생성 (AI 모델)**
  - 정제된 뉴스 내용을 기반으로 **대화형 시나리오** 생성
  - 예: "가짜 검찰청 직원이 전화를 건다" → 실제 전화 대화 형식으로 변환
- **검증 (AI 채점 모델)**
  - 1차 룰 기반 필터: 너무 짧은 대화 / 욕설 포함 / 필수 요소 누락 시 Reject
  - 2차 LLM 채점: 시나리오 품질 평가 (1~5점) → 3점 이상일 때 DB 등록

저는 이 중에서 **AI 모델을 활용한 시나리오 생성**을 맡고 있습니다. 즉, 뉴스를 단순 요약하는 수준이 아니라, 실제 보이스피싱 상황처럼 **대화형 시나리오로 재구성하는 것**이 제 역할입니다.  
추후에는 중복 시나리오 방지(임베딩 기반 유사도 검사 등), 시나리오 다양성 확보, 관리자 검수 시스템 도입 같은 기능을 추가해 서비스의 완성도를 높일 계획입니다.

## 🏠 AI 모델 활용 방식 탐색

---

뉴스에서 얻은 텍스트를 단순 요약하는 것이 아니라, **대화형 사기 시나리오**로 재구성하는 것이 제가 맡은 핵심 과제입니다. 다만, 다음과 같은 제약 조건이 있습니다.

> - **최신 뉴스 반영 가능성**: 매일 새롭게 업데이트되는 기사를 처리해야 하므로, 지속적으로 학습하거나 프롬프트 기반으로 유연하게 생성할 수 있는 모델이 필요합니다.
> - **개인정보 및 보안 이슈**: 어르신 대상 서비스이기 때문에, 민감한 데이터(실제 피해자 이름 등)가 들어가면 안 됩니다.
> - **실시간성**: 하루 단위로 업데이트되는 시나리오를 생성해야 하므로, 과도한 연산 자원 소모 없이 빠르게 실행 가능한 모델이 적합합니다.

이러한 제약 조건을 충족하고 최신 뉴스 기반의 대화형 시나리오를 자동 생성하기 위해, **LLM**을 활용합니다.

> ✔️ LLM (대형 언어 모델, Large Language Model)이란?
> 방대한 텍스트 데이터를 학습하여 자연어 이해와 생성이 가능한 모델
> 문장 생성, 요약, 번역, 대화 등 다양한 NLP 작업 수행 가능

### LLM 활용 방식 후보 및 대표 모델

| 후보                             | 대표 모델 / 예시                                               | 특징                                                         |
| -------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------ |
| **오픈소스 LLM (프롬프트 기반)** | LLaMA, Mistral, Falcon, GPT4All                                | 모델 그대로 사용, 프롬프트만 조정, 도메인 특화 없음          |
| **오픈소스 LLM 파인튜닝**        | LLaMA, Mistral, Falcon                                         | 사기 시나리오 데이터로 Fine-tuning, 도메인 특화 가능         |
| **LoRA / 경량 파인튜닝**         | LLaMA+LoRA, Mistral+LoRA, Falcon+LoRA                          | 일부 파라미터만 학습, 적은 데이터로 도메인 특화 가능         |
| **API 기반 모델**                | OpenAI GPT-4, Claude, Anthropic Claude, Cohere Command         | 클라우드 API 호출, 바로 사용 가능, 안정적 품질               |
| **RAG**                          | LLaMA, Mistral, GPT 계열 + 벡터 DB (Weaviate, Pinecone, FAISS) | 정제된 뉴스 DB 검색 후 LLM으로 시나리오 생성, 최신 정보 반영 |

> **💡 개발 방향 (MVP 단계)**
> 데이터와 비용 제약으로 인해 LLaMA 같은 대형 모델을 직접 Fine-tuning하는 것은 어렵습니다.
> 따라서 우선은 **RAG 방식을 활용해 시나리오를 생성**하고, 서비스 안정화 및 충분한 시나리오 데이터 확보 이후 **LoRA 등의 경량 파인튜닝 기법**을 적용하여 도메인 특화를 진행할 계획입니다.

다음 포스팅에서는 **RAG(Retrieval-Augmented Generation) 방식을 자세히 살펴보고,** 이를 활용해 실제 시나리오를 생성하는 과정에 대해 다뤄보겠습니다.
